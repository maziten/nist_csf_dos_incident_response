
# Lessons Learned: ICMP Flood DoS Incident

## Project Reflection

This project helped me understand how a firewall misconfiguration can expose an organization's network to a Denial-of-Service (DoS) attack and how the NIST Cybersecurity Framework can guide incident response.

## Key Lessons

### 1. Secure Configuration Matters

An improperly configured firewall can create a security gap that attackers may exploit. Regular configuration reviews and security audits help identify these weaknesses.

### 2. Layered Security Is Important

No single security control can address every threat. Firewall rules, ICMP rate limiting, source IP address verification, network monitoring, and IDS/IPS can work together to reduce risk.

### 3. Early Detection Reduces Impact

Monitoring network traffic and setting alerts for unusual ICMP activity can help security teams identify potential attacks before they cause prolonged disruption.

### 4. Incident Response Needs a Plan

A clear incident-response plan helps teams contain suspicious traffic, investigate the cause, communicate effectively, and restore critical services.

### 5. Recovery Is Part of Security

Restoring services is not the final step. Teams should verify that systems are functioning correctly, monitor for further suspicious activity, and review what can be improved.

## Applying the NIST Cybersecurity Framework

The five functions work together:

- **Identify:** Find vulnerabilities and understand risks.
- **Protect:** Implement safeguards to reduce risk.
- **Detect:** Identify suspicious activity.
- **Respond:** Contain and investigate incidents.
- **Recover:** Restore operations and improve resilience.

## What I Learned

I learned that cybersecurity involves more than identifying an attack. It also requires understanding the weakness that allowed it, choosing appropriate security controls, coordinating an effective response, and preparing for recovery.

This exercise improved my understanding of how the NIST Cybersecurity Framework can be applied to a simulated network security incident.
